# Phase 12 — Production hardening (2.0)

Migrate-on-startup, bounded Meta retries with latency observability,
auth rate limiting, backup/restore, and full downgrade verification —
plus the real schema bug this work uncovered and fixed.

## What was built

- `backend/app/core/database.py`: `init_db()` runs `alembic upgrade head`
  on postgres first; create-all-plus-stamp stays as a never-block-startup
  fallback; sqlite unchanged (unmanaged).
- `backend/alembic/env.py`: `DATABASE_URL` env wins over the ini default;
  `-x url=...` wins over both (scratch-DB work); `compare_server_default=True`
  so autogenerate sees default drift.
- `backend/alembic/script.py.mako`: restored the standard revision template
  (was missing — autogenerate could not run in-container).
- `backend/app/services/meta_http.py` (new): shared transport — retries
  transport errors / 429 / 5xx (`META_RETRIES`, default 1 extra attempt,
  linear backoff), other 4xx returned immediately (retrying them doubles
  cost for zero benefit). Every attempt logs label/model/attempt/
  duration_ms/status. No cost figures are logged — the Meta API returns
  none, so none are invented.
- `asr_providers.py` + `muse_spark_service.py`: use the shared transport.
  All error codes/messages byte-identical (`ASR_TRANSPORT`,
  `ASR_UNAUTHORIZED` non-retryable, `ASR_RATE_LIMIT`, `ASR_ERROR`; Spark
  `401/429/error` RuntimeErrors). Timeouts unchanged (120 s ASR, 90 s Spark).
- `backend/app/middleware/rate_limit.py` (new): per-IP fixed window on
  `/api/v1/auth/*` (`RATE_LIMIT_PER_MINUTE`, default 120), structured 429
  (`RATE_LIMITED`, `retryable: true`). Single-process scope, documented —
  multi-replica needs a shared store.
- `backend/app/main.py`: middleware registered; startup warns on dev
  `JWT_SECRET`.
- `infrastructure/scripts/backup.ps1` / `restore.ps1`: binary-safe dump
  (no shell redirection) to git-ignored `backups/`; restore defaults to
  scratch `restorecheck`, `-TargetDb secondvoice` for real restores.
- `infrastructure/scripts/verify_migrations.ps1`: downgrades every revision
  to base on scratch, upgrades back, asserts version pointers match and the
  chain-built schema is identical to live.
- `backend/tests/test_production.py`: 7 tests (retry-then-success for
  transport and 429, 400 never retried, exhaustion raises, auth 429 shape,
  non-auth paths unaffected, broken migrations never block startup).
- `.gitignore`: `/backups/` + `*.dump` (dumps carry password hashes).
- `docs/deployment.md` §§4/6 updated (auto-migrate, new scripts, new knobs).

## The schema bug this phase found (and fixed)

The schema-identity check proved the migration chain did NOT reproduce
`app/models.py`: chain-built columns were nullable where models require
`NOT NULL`, and carried server defaults models never declared (client-side
`default=` instead). Root cause: 0001 was hand-written loosely and the live
DB grew from historical `create_all` runs, so nothing ever compared them.

- `0010_schema_conformance`: autogenerated + audited (pure SET NOT NULL,
  100+ columns, no table/column/index changes).
- `0011_drop_non_model_defaults`: autogenerated + audited (62 ops, each
  `nullable=False` + `server_default=None`; `created_at now()` untouched;
  downgrade restores old defaults).
- After both: full-chain schema identical to live (MIGRATION-ROUNDTRIP-PASS).

## Validation (Docker, observed)

- Live DB self-migrated 0009 → 0010 → 0011 across container rebuilds, no
  manual step (`current` confirms each head).
- `verify_migrations.ps1`: 11 downgrades to base, upgrade to head, pointers
  match, schemas identical — MIGRATION-ROUNDTRIP-PASS.
- `backup.ps1` → 110 KB dump; `restore.ps1` to `restorecheck` → 23/23 users
  match live. Scratch DBs dropped afterwards.
- Rate limit live: exactly 120 × 401 then structured 429s
  (RATELIMIT-DOCKER-PASS). Note: the probe consumed its own window — the
  next register attempt right after returned 429 until the minute reset;
  re-probe then passed (PHASE12-SMOKE-PASS).
- Suite: 102/102 passed (7 new, no regressions).

## Honest limits

- Retries add at most one extra Meta call per request (cost/latency bounded,
  visible in `meta_call` logs); 4xx (except 429) never retried.
- Rate limiter is per-process memory: correct for single-node Compose only.
- Downgrades of 0010/0011 restore looseness, not data — downgrading past
  0002–0009 drops added columns by design (documented, never run on live).
- TLS, multi-node, and log-based cost dashboards remain out of scope
  (see deployment §§3/7).
