# Phase 8 — Adaptive Clarification (done 2026-11-01)

## What was built and why

Ambiguity used to produce one generic "please repeat that". Phase 8
asks about the uncertain span: which word, which readings, with the
actual options on screen — plus type-your-own, saved-phrase, skip, and
audio replay. High-impact ambiguity gates confirmation until answered,
skipped, or explicitly overridden.

## Design (`services/clarification_service.py`, pure + deterministic)

Questions are **built from stored evidence, never generated by an LLM**
— options must be readings someone or something actually produced:

1. Engine meaning-divergence → one blocker ("which did you intend?",
   both readings labelled by engine).
2. Ambiguous personal patterns (one question per term, readings from
   the user's own corrections) → blockers.
3. Language mismatch → advisory (which language to speak).
4. Wording-only engine disagreement → advisory (max 2).
5. Fallback: the model's generic clarification question, advisory.

Budget: max 3, blockers first. Grammar-only diffs (articles, copula,
punctuation) are never interrogated. Answering **or explicitly
skipping** resolves — skipping records uncertainty preserved, not
hidden. Select validates against offered option ids; free text is
1–200 chars.

## Gate + replay

- `Suggestion.clarification_answers` JSON (migration `0007`).
- `GET /reconstruction/questions/{id}` (questions + answers +
  unresolved blockers + audio replay URL),
  `POST .../answer {question_id, kind, value?}` (404 unknown question,
  422 bad value).
- Confirmation returns 409 `CLARIFICATION_PENDING` while blockers stand;
  `force: true` overrides with an audited `forced_over` list — user
  authority always wins. Applies to transcript-direct confirms too.
- `GET /audio/sessions/{sid}/audio/{aid}` replays the **original**
  recording (ownership + retention checked; expired 410s). Full clip
  only: per-segment replay needs word timings no provider exposes.

user-driven at confirm); old Wonder clarify path untouched; `0007`
