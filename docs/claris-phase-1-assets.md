# CLARIS Phase 1 — Audio asset architecture

Original preservation, derivative lineage, normalization output, QA per
derivative. No enhancement, no restoration (those are P4/P5).

## What was built

- `AudioDerivative` model (`audio_derivatives`): parent FK with DB-level
  CASCADE, kind (`normalized`/`enhanced`/`restored`/`generated`), operation,
  model_version, config, file, QA, status/error, timestamp.
  `AudioAsset.derivatives` backref with ORM delete-orphan cascade.
- Migration `0012_audio_derivatives`: autogenerated with
  `compare_server_default=True`, audited (creates one table only);
  `0012 (head)` confirmed live via migrate-on-startup.
- `derive_normalized(db, asset)`: reads the original file only, writes a
  sibling `_normalized_16k.wav`, stores output QA (`analyze_wav16k`),
  idempotent per (parent, operation, version) — reruns return the same row,
  no duplicate files.
- Endpoints (ownership-checked, retention-checked):
  `POST …/audio/{id}/normalize`, `GET …/derivatives/{did}` (audio/wav replay).
- History: session detail items list each audio's derivatives
  (transcribed audios; untranscribed-audio listing arrives with the P8
  comparison workspace).
- Wipe (`DELETE /account/data`) now also deletes derivative files
  (rows go via DB cascade).

  idempotent rerun, playback 200 + cross-user 404s, untranscribed-audio
  normalize works, missing-file 410, wipe removes files).

## Honest limits

- Only `normalized` is produced; `enhanced`/`restored`/`generated` kinds
  exist in the model for P4/P5/P9 but no code path creates them yet.
- No denoising/VAD stage in P1 (stdlib + miniaudio only; enhancement model
  selection with license + CPU checks is P4 work alongside restoration).
- Derivative listing is per-transcript-item; a standalone comparison view
  is P8.
