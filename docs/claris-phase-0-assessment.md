# CLARIS Phase 0 — Repository assessment and implementation plan

Date: 2026-11-04. Tree: `main` at `de1900b`, clean (only known strays:
`Microsoft/`, `pip/`, `backend/dbg_probe.py`, `frontend/tsconfig.tsbuildinfo`).
Suites: backend 102/102, frontend 15/15. Docker: db + backend healthy,
frontend serving; Meta ASR live.

## 1. What works today (verified live, keep)

- Auth + per-user isolation; audio upload/storage/playback with consent and
  retention; in-browser WAV conversion (`toWav16kBlob`) so the server only
  ever receives decodable WAV.
- ASR: Meta Muse Voice Transcribe behind `ASRProvider` interface +
  orchestration (`asr_providers.py`, `asr_orchestration.py`), conditional
  second engine (none benchmarked), agreement endpoint, reliability notes.
- Evidence: `uncertainty_service.py`, `Transcript.evidence`,
  `audio_intelligence.py` (quality/noise/clipping — advisory, never blocking).
- Reconstruction: rules-first + Muse Spark, extended meaning guards
  (negation/numbers/names/dates/modals/conditionals/units/medical),
  abstention, question-blocked confirm (409), alternatives, clarification
  Q&A with audio replay (`clarification_service.py`).
- Personalization: user vocabulary (also sent as ASR keyword hints),
  corrections, patterns, provenance/versioned revisions, wipe, review UI.
- Cards board (tap-to-speak through the confirmed path), TTS with
  server-side confirmation gate, interaction metrics, study harness,
  migrate-on-startup, retries, rate limiting, backup/restore scripts.
- Languages: en/hi/hinglish/mr + extensions; explicit per-recording hint
  now wired in the workspace ("I speak" selector).

## 2. What is incomplete or missing (vs this spec)

- No original-vs-derivative model: `AudioAsset` has one file reference;
  no `AudioDerivative`, `RestorationJob`, or processing lineage.
- No enhancement pipeline (only advisory quality analysis; no denoise/VAD/
  normalize stage) and no enhancement-vs-original ASR comparison.
- No speech-restoration provider of any kind (no `speech_restoration/`
  package, no inference container, no model weights).
- ASR bench limited to Meta (+dev fallback); no Whisper/Conformer adapters,
  no Hindi-specific engine, no speaker-disjoint harness on atypical speech.
- Missing-word suggestions exist only as contextual Spark output; no
  source-labelled candidate categories (acoustic vs alternative-ASR vs
  contextual vs vocab).
- No acoustic speaker adaptation; no consent-gated calibration dataset flow.
- TTS: no Hindi/English voice expansion work; no cloning (correctly absent).
- Frontend: no audio-comparison workspace (original/enhanced/restored
  players), no per-language recording gate ("require hi|en before record"
  is a selector default, not a gate), no derivative-unavailable states.
- No TORGO/UASpeech access; no atypical-speech evaluation data at all.

## 3. Reusable services (extend, do not duplicate)

`audio_service.py` (ingest/decode), `asr_providers.py` + `asr_orchestration.py`
(new providers plug in here), `uncertainty_service.py`,
`reconstruction_service.py` (candidate categories attach to the existing
guard/suggest flow), `personalization_service.py` (correction memory),
`clarification_service.py`, `evaluation_harness.py` + `evaluation_service.py`
(WER/CER/guards/span retention), `meta_http.py` (bounded retries for any new
HTTP inference), migrations 0001–0011 chain, Docker Compose (new `inference`
service alongside, not inside, `backend`).

## 4. Required changes (by phase)

- P1: `AudioDerivative` model + migration; derivative pipeline stages;
  preservation tests; storage layout `original/normalized/enhanced/restored/
  generated` as metadata categories on the existing volume.
- P2: provider adapters (Whisper-small, whisper-small-hindi, SraVaani,
  IndicConformer — verify license + Hindi quality each); bench script
  reusing the harness; record per-provider latency/resource/failure.
- P3: reproduce `CLARIS-Inference` notebook locally (needs GDrive access);
  record checkpoint hashes, sample rate, duration limits, CPU latency.
- P4–P5: `services/speech_restoration/` package + `inference/` container;
  transcript comparison across original/enhanced/restored.
- P6: source-labelled suggestion categories in the existing suggest flow.
- P7: correction-memory ranking first; calibration-flow tables only.
- P8–P9: workspaces + voice expansion (Google Cloud TTS; XTTS-v2 excluded).
- P10: speaker-disjoint atypical-speech eval; perf + limitations report.

## 5. Regression risks

- Migrations 0010/0011 made the chain exactly equal `models.py`; new
  tables must come as autogenerated migrations (keep
  `compare_server_default=True`).
- The confirmation gate and evidence hierarchy are load-bearing safety
  properties — every new pipeline reuses them, never bypasses.
- Frontend in-browser WAV path must stay the single ingest format.
- Full suites (102 + 15) stay green; no test weakening.
